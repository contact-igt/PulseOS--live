## Key rulings (recorded here, mirrored in ledger)

- **Attribution model (§11 of the prompt):** full touchpoint history is canonical;
  first touch = immutable earliest meaningful acquisition touch; last touch = latest;
  both are *derived views* over the touchpoint table, not separately-maintained
  duplicate fields. This resolves the audit's `touchType` conflict — visual-recon's
  `domain/campaign`/`domain/lead` code that writes only `first_touch` gets replaced by
  a call into the acquisition branch's `attribution.service.ts` logic (ported, not
  duplicated).
- **Migrations (§10):** visual-reconstruction's applied history (`0000`–`0007`) is the
  base. Acquisition's unique schema (conversion_feedback_events, gbp_performance_metrics,
  connector_disposition_mappings, connector_config_audit_events, plus any touchpoint
  column additions) is added via **new** migration(s) starting at `0008`, generated by
  `drizzle-kit` from the merged `schema.ts` — never by copying acquisition's `0005`-`0009`
  files verbatim (their numbering collides with visual-recon's own `0005`-`0007`).
- **Exotel/Superfone (§15):** not built this checkpoint. UI rows stay, explicitly labeled
  "Not available yet", never shown with a healthy/LIVE treatment.
- **`/treatment` → `/treatments` (§16):** compatibility redirect, not two pages.
- **AI Agent Runtime (§24):** explicitly out of scope. `AI_RESUME_PENDING` stays inert.
